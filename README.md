# 2030 SDGs Game｜完整使用說明

更新：2026年10月20日。本說明對應目前「依日期累積場次、交易所免登入」版本。

## 1. 三個固定入口

|入口|用途|密碼|
|---|---|---|
|[SDGs交易所紀錄](https://sdgs-exchange.pages.dev/exchange)|共用手機輸入組別、角色代號、專案代號，完成交易|不需要|
|[世界看板](https://sdgs-exchange.pages.dev/dashboard)|投影三項指標、曲線，反思時顯示轉折|不需要|
|[引導師後台](https://sdgs-exchange.pages.dev/admin)|場次、交易階段、撤銷、統計及下載|需要原有引導師密碼|

首頁：https://sdgs-exchange.pages.dev 。密碼不列入本說明，請沿用已另行提供的登入資料。

同一時間只有一場目前活動。公開交易所與看板永遠跟隨目前活動；在後台點選歷史場次，不會切換公開頁面。現場請使用你準備的手機輪流登錄。開放期間，其他持有網址的人也能登錄；結束時請暫停或進入反思。

## 2. 每場活動前

1. 電腦開後台並登入，手機開交易所，投影設備開世界看板。
2. 確認各頁顯示「已同步」及相同活動名稱、日期。
3. 若使用現有未封存活動：填入活動名稱與舉辦日期，按「儲存名稱與日期」。原有資料移轉的場次名稱為「原有活動（可修改名稱與日期）」，日期請改成實際舉辦日期。
4. 若要新開一場：先回到目前活動，暫停並封存上一場，再展開「建立下一場活動」，填名稱、日期，按「建立活動」。未封存前不能建立下一場。
5. 新場次交易從0開始，經濟、環境、社會均從3開始；預設A–P共16組，卡庫沿用上一場80張卡。
6. 展開「活動準備」，確認已匯入80／80張。組別、卡庫僅能在準備階段且完全沒有交易紀錄時修改；曾有交易即使全部撤銷，仍不可替換。
7. 手機初次載入預選H組；每筆請依實際參與組別選擇。送出後保留目前選組，不會自動跳回H。
8. 現場準備完成後，按「開放交易」並確認。等手機顯示「交易進行中」再開始。

正式活動前演練建議另建名為「測試」的場次，測完封存，再建立正式場次；避免把演練紀錄混入正式活動。封存測試場也會列入歷史場次總計。

## 3. 參與者登錄流程

1. 工作人員先確認實體專案已完成、資源與執行條件符合規則。
2. 在共用手機選擇正確組別。
3. 選擇角色代號：1 財富追求者、2 悠閑追求者、3 消滅貧困戰士、4 保護環境鬥士、5 社會正義使者；再輸入執行的專案代號1–80。
4. 按「確認回報資訊」。此時只顯示核對視窗，尚未計次。
5. 核對組別、角色代號、專案代號及卡名。錯誤按「返回修改」；正確按「完成交易」。
6. 等待「某組交易成功！紀錄 #編號」，才交給下一位使用。

下方「本場SDGs有效交易 N 次」是目前場次所有組別的有效交易合計，不是所選組的次數。各組次數請看引導師後台。已撤銷交易不計入。

同一卡可以重複執行；每次重新核對並按完成交易，視為新的行動。系統不會依相同卡號自動去重，所以不能用「再登錄一次」確認上次是否成功。

## 4. 確認與重試的差別

|操作|作用|是否增加交易|
|---|---|---|
|確認專案|開啟核對視窗|否|
|返回修改|關閉視窗、修改輸入|否|
|完成交易|送出新交易|成功時新增一筆|
|重試上一筆交易|重送同一個識別碼|原筆成功則不新增；原筆未成功才補登|

重試按鈕只在結果不明時顯示，例如網路斷線、逾時或伺服器未能回應。請保留同一分頁，恢復網路後按重試。此時新交易暫時停用，避免覆蓋待確認資料。重複傳送相同識別碼只計一次。

若系統明確回覆「此筆未登錄」，例如活動已暫停、已封存、切換場次或卡號無效，會解除待重試狀態。先確認活動、組別、卡號與交易階段，再重新操作。

若關閉分頁或清除瀏覽資料，待確認識別碼可能遺失。請先由引導師查後台交易紀錄；不要直接補登，以免另產生一筆。若舊筆已撤銷，重試不會把它恢復。

## 5. 階段與操作規則

|階段|可新增交易|轉折公開|管理重點|
|---|---|---|---|
|準備中|否|否|確認80張卡、組別、名稱日期|
|交易進行中|是|否|監看同步、現場輪流登錄|
|已暫停|否|否|查核、撤銷誤登，之後可重新開放|
|反思階段|否|是|回顧曲線、相關卡片與關鍵事件|
|已封存|否|是|紀錄唯讀，可查閱下載，建立下一場|

未封存活動可再次開放交易；若已展示轉折，重新開放雖會隱藏轉折，參與者已看過的資訊無法收回，請由引導師決定是否適合繼續。

系統不會依時鐘自動開始或結束，日期是管理標籤。所有階段需由引導師手動操作。

## 6. 誤登與撤銷

1. 在後台回到目前活動，按「暫停交易」。
2. 在交易表找到錯誤筆，核對流水號、組別、卡號與時間。
3. 按「撤銷」，輸入原因。
4. 系統保留原紀錄與原因，重新按剩餘有效交易順序計算世界狀態與各組次數。
5. 核對後按「開放交易」。若原行動仍需記錄，再於交易所輸入正確組別、卡號。

撤銷沒有直接復原按鈕。補登是新的交易，位置在當下序列末尾，不會插回原位置。因每一步最低為0，補登順序不同可能影響結果。請在封存前完成核對。

## 7. 世界狀態如何計算

經濟為藍色實線、環境為綠色長虛線、社會為黃色點線。

每場起始值皆為3；每筆有效交易依卡片增減更新，計算方式為「新值＝max(0，前值＋該卡增減)」，最低0，沒有設定上限。這是每筆逐步計算，不是全部加總後才歸零。

例如起始3，先減5得到0，再加2得到2。若撤銷減5那筆，重算後為5。

交易順序依資料庫流水號，不依手機時間。流水號跨場次持續累計，撤銷也可能造成缺號；曲線的「第N筆有效交易」則是該場排除撤銷後的次序，兩者不一定相同。

頁面約每2.5秒同步一次。同步中斷時保留最後成功資料並顯示提示，不能把舊數字當成即時狀態。

## 8. 反思與轉折揭露

遊戲進行中公開看板顯示指標、曲線及總交易數，不顯示轉折分析。

按「進入反思／揭露轉折」後停止收件，公開看板與後台顯示事件列表，包含有效交易次序、組別、卡號、卡名及經濟／環境／社會前後數值。

目前篩選規則為：任一指標歸零、從零回升，或單筆實際變化的幅度至少2。列表用於討論，不是自動判定因果，也不是所有方向反轉或趨勢變化的完整分析。曲線目前不提供點擊資料點彈出卡片的互動功能。

可問參與者：當時想達成什麼？哪項指標受到影響？不同組別的選擇如何累積？如果重來，會如何協作？

## 9. 結束、封存與下一場

1. 進入反思，完成撤銷與核對。
2. 檢查活動名稱、日期；封存後無法修改。
3. 按「下載活動紀錄」，保存JSON。
4. 按「結束並封存此活動」，確認。
5. 封存後可再下載一份，保留封存狀態。
6. 下一場到來時，回到目前活動，建立新名稱與日期的活動。

不需換資料庫、不需清空交易、不需另建網站。新活動沿用80張卡，但擁有獨立的交易紀錄、組別及世界狀態。舊場次不被覆蓋。

## 10. 歷史查閱與備份

後台用「篩選月份」尋找活動，點選場次可看該場統計、曲線、轉折與交易明細。歷史場次唯讀；查看歷史不會讓現場手機切換到舊活動。按「回到目前活動／更新清單」返回。

「下載活動紀錄」下載目前後台正在查看的那一場，不是全資料庫。JSON包含場次資訊、有效交易統計、曲線資料、交易與撤銷資訊、該場卡片快照；反思／封存狀態含轉折事件。檔名含日期與活動名稱。

JSON是報表資料，目前沒有從JSON自動還原的介面。建議每場下載後另外保存於自己的雲端資料夾；完整災難復原需另備份Cloudflare D1資料庫。保留網站與Cloudflare帳號才能持續使用，資料庫保存不等於獨立備份。

## 11. 常見狀況

|狀況|處理|
|看不到新名稱或功能|重新整理頁面，必要時關閉舊頁再開固定網址；有待確認交易時先查核|
|確認專案按鈕灰色|檢查是否已開放、是否已同步、是否有待重試交易及80張卡是否載入|
|選錯組別但還沒送出|返回修改後重新確認|
|已送出才發現錯誤|引導師暫停、撤銷，再視需要補登|
|反思／封存後不能交易|屬正常行為；未封存可重新開放，已封存則建立下一場|
|無法建立下一場|回到目前活動，確認已封存；歷史檢視下不能直接建立|
|無法改組別／匯入卡庫|僅限準備階段且沒有任何交易；新場次設定請在開放前完成|
|數字和上一個畫面不同|確認是否相同場次、同步成功，及是否有人新增或撤銷交易|
|按重試仍出錯|保留分頁，請引導師查紀錄與連線；不要另開新交易嘗試|
|忘記後台密碼|使用先前提供的登入資料；需要變更時在Cloudflare更新ADMIN_TOKEN並重新部署|

## 12. 使用範圍與資料核對

本系統記錄已完成的專案行動與世界變化，不自動扣除金錢／時間、不判定實體卡執行資格，也沒有參與者個人帳號。資源與執行門檻仍由現場工作人員依原遊戲規則核對。

正式80張卡依提供的Excel轉換。第22號「保障女性就業機會」依原檔為經濟−1、環境+1、社會−2，開場前請對照實體卡；系統未依卡名擅自更改值。

## 13. 本機備援與維護

完整版程式包含本機伺服器與正式卡資料。Node.js 22.13以上可執行，建議24。開啟「啟動活動.command」，輸入引導師密碼；交易所不需密碼。本機資料與雲端資料是兩套獨立資料，不會互相同步，切換備援前須決定使用哪一套，避免分散登錄。

本機資料在data/game.sqlite。各場仍透過後台管理，不要為了下一場刪除資料庫。停止本機服務後再備份整個data資料夾。手機與電腦須能透過同一網路互連，使用電腦區域網路IP的8788埠。

Cloudflare既有正式資料庫已升級，日常活動不要重跑建表或遷移SQL。全新部署才先執行schema.sql，再執行migrations/002-activities.sql一次，設定DB綁定與ADMIN_TOKEN，再部署Pages Functions。OPERATOR_TOKEN已不再是交易所使用條件。

## 14. 現場一分鐘檢查表

- 活動名稱、日期正確；80張卡、16組確認。
- 手機、看板、後台顯示同一場且已同步。
- 引導師開放交易後，參與者才登錄。
- 每筆等成功訊息再交給下一人；看卡名，不只看卡號。
- 結果不明重試原筆；誤登先暫停再撤銷。
- 結束進入反思、核對、下載、封存；下一場另建活動。
